# java-calculator-precourse

# 구현 기능 목록

## 입력 처리

- 빈 문자열 입력 처리(결과 : 0)
- 기본 구분자(쉼표, 콜론)를 이용한 숫자 분리
- 커스텀 구분자 지정 및 처리("//" 와 "\n" 사이의 문자)
- 기본 구분자와 커스텀 구분자 둘 다 사용 가능
- 숫자 추출 및 연산

## 검증 및 예외처리

### 입력값 검증

- 빈 문자열 체크
- 숫자만 존재하는지 검증
    - 음수 입력시 예외 발생
    - 숫자가 아닌 문자 입력 시 예외 발생
    - 구분자가 연속으로 나오는 경우 (1,,2) 예외 발생
    - 문자열 끝에 구분자가 있는 경우 (1,2,) 예외 발생

### 커스텀 구분자 검증

- "//"로 시작하지만 "\n"이 없는 경우 예외 발생
- 커스텀 구분자가 빈 문자열인 경우 예외 발생
- 커스텀 구분자 이후 개행 후 숫자가 없는 경우 예외 발생

### 기타 예외 처리

- 잘못된 형식의 문자열("//;1;2;3"-"\n") 예외 발생
- 지정되지 않은 구분자가 포함되는 경우 예외 발생

# 고민한 것

- 의존성 주입을 어떤 방식으로 진행할지, 싱글톤을 지키며 어떤 방식으로 구현해야할지 고민함.
- 의존성 주입을 분리해서 config파일을 만들어야 할지 아님 규모가 작기에 그냥 각 클래스에서 싱글톤을 지키면서 주입해도될지 고민함.
- 검증 클래스에서 한 메서드가 너무 많은 책임을 가지고 있기에 분리를 하는 게 좋을지 아니면 코드 자체가 지저분해서 다시 구현해야할지 고민함.
- 단일 책임 원칙에 맞게 최대한 분리해서 구현했지만 끝까지 정확한 해답을 찾지 못했음.

# 트러블 슈팅
-----

### 문제

- 터미널에 "//;\n3;3" 입력값을 줬을 때 계속 에러가 발생함.

### 해결

- 터미널에 입력값을 줬을 때 "\\n" 이렇게 이스케이프 시퀀스로 입력해야 함을 알게 됐음

------

### 문제

- split 함수로 구분자를 기준으로 숫자를 구분했는데 구분자가 처음이나 끝에 위치했을 때 빈문자열은 무시해 검증을 제대로 수행하지 못함

### 해결

- split 함수 인자로 구분자와 -1을 넣어 빈문자열도 배열에 넣어서 체크해서 예외를 던짐

------

### 문제

- 구분자를 정규식을 사용해서 처리했는데 커스텀 구분자를 지정할 때 정규식 특수문자(^,[ 등)를 사용하면 버그가 발생함

### 해결

- 정규식을 사용하지 않고 HashSet을 사용해 기본 구분자와 커스텀 구분자를 정규식으로 변환해서 관리하지 않고 관리함

------
